# پرامپت تحویل پروژه به یک دستیار کدنویسی (Claude Code / چت لوکال)

> این متن را کامل کپی کنید و در ابتدای گفتگو بدهید. مخزن باید کلون شده باشد.

---

تو یک مهندس نرم‌افزار ارشد هستی و ادامهٔ یک پروژهٔ واقعی را تحویل می‌گیری. فارسی جواب بده، کد و کامیت‌ها انگلیسی.

## پروژه چیست
سامانهٔ مدیریت چادرهای زائران حرم مطهر شاهچراغ (ع). حدود هزار چادر هر کدام یک برچسب ساتنی با QR (`CH-000001` …) دارند. خادمان گیت چادر را به زائر تحویل می‌دهند و پس می‌گیرند؛ چادر کثیف به کارگاه شست‌وشو می‌رود، بررسی می‌شود و دوباره آماده می‌شود. دفتر آمرین نظارت می‌کند.
مخزن: github.com/FotoohiDeveloper/ChSh ، شاخهٔ کاری `ccr-8fe79f7c-fapwqg` (فقط روی همین شاخه کار کن؛ بدون درخواست من PR نساز).

## ساختار مخزن
- `backend/` Go 1.26، PostgreSQL 16، Redis 7، Docker Compose، Caddy. یک باینری با زیرفرمان‌های `serve | worker | migrate | create-admin | seed-places | import-tents | healthcheck`. مستندات: `backend/README.md`، `docs/API.md`، `docs/SECURITY.md`، `docs/OPERATIONS.md`.
- `android/core/` کوتلین خالص JVM: کلاینت API، نشست، صف آفلاین + sync idempotent (`op_id`)، اعتبارسنج‌ها (کد ملی، موبایل، تاریخ شمسی)، و همهٔ منطق صفحه‌ها در قالب Presenter با StateFlow. ۴۶ تست.
- `android/app/` Jetpack Compose (Material3، RTL، فونت وزیرمتن)، اسکنر CameraX + ML Kit، ذخیرهٔ توکن با Android Keystore، WorkManager. در CI روی GitHub کامپایل می‌شود؛ روی دستگاه واقعی هنوز آزمایش نشده.
- `labels/` تولید PDF برچسب (۳۲×۴۰ میلی‌متر، QR، متن «حرم مطهر شاهچراغ» بالا و شناسه پایین).
- `.github/workflows/` `backend.yml` و `android.yml`.

## نقش‌ها
admin، office (دفتر آمرین)، gate_lead (مسئول گیت)، server (خادم)، team (تیم تخصصی چادر)، workshop، service. نقش‌های عملیاتی قبل از کار «شیفت» (محل + درب) شروع می‌کنند. وضعیت چادر: ready → with_pilgrim → dirty → in_wash → pending_review → ready/repair/retired. زائر با کد ملی + تاریخ تولد + موبایل ثبت می‌شود. چند چادر برای یک زائر ممکن است؛ جوراب رجیستر جدا دارد؛ لغو تحویل تا ۳ دقیقه؛ درخواست خروج از چرخه با تأیید دفتر؛ تحویل شیفت؛ گزارش روزانه + اکسل؛ یادآور پیامکی؛ ناشناس‌سازی بعد از ۹۰ روز؛ audit log فقط-افزودنی.

## امنیت و طراحی (حفظ کن)
اطلاعات شخصی با AES-256-GCM رمز و با HMAC شاخص‌گذاری می‌شود؛ توکن‌های opaque در Redis (۱۵ دقیقه + refresh یک‌بارمصرف)؛ دو نقش دیتابیس (owner برای migrate، `chador_app` بدون DDL و بدون UPDATE/DELETE روی audit/tent_events)؛ rate limit؛ همهٔ عملیات تغییر وضعیت با `op_id` تکرارپذیرند؛ شبکه‌های Docker جدا؛ کانتینرها `read_only` و `cap_drop: ALL`.

## وضعیت فعلی
- تست‌های بک‌اند (با `-race`) و `android:core` در CI سبزند؛ build دیباگ اندروید سبز است.
- سرور تولید: `ssh -p 9011 root@194.60.230.36` ، مسیر `/opt/ChSh` ، دامنه `shch.badr-group.ir` ، نصب با `backend/deploy/install.sh` انجام شده (کانتینرها healthy). رکورد A دامنه باید `194.60.230.36` باشد (قبلاً روی IP دیگری بود؛ بررسی کن).
- فعلاً `INQUIRY_MODE=off`، `SMS_MODE=off`، `ALLOW_UNVERIFIED=true` (حالت آزمایشی؛ هویت زائر واقعاً استعلام نمی‌شود).
- کارهایی که روی سرور باید تمام شوند/بررسی شوند: `seed-places`، `import-tents` (فایل `labels/output/tent_ids.csv`)، گرفتن گواهی HTTPS توسط Caddy، تغییر رمز admin، ساخت درب‌ها و کاربران، پشتیبان‌گیری `deploy/backup.sh` با cron، و نگهداری نسخهٔ آف‌سرور از `deploy/secrets/pii_enc_key` و `pii_idx_key` (گم‌شدنشان یعنی از دست رفتن همیشگی داده‌های رمزشده).

## کارهای باز (به ترتیب اولویت)
1. تحویل و راستی‌آزمایی استقرار: `curl https://shch.badr-group.ir/readyz`، ورود admin، یک چرخهٔ کامل تحویل/دریافت با برنامهٔ اندروید.
2. اتصال سرویس‌های واقعی: قرارداد API استعلام هویت و پیامک در `backend/internal/provider/provider.go` عمومی است و باید با سرویس‌دهندهٔ واقعی تطبیق داده شود؛ سپس `INQUIRY_MODE=http`، `SMS_MODE=http`، `ALLOW_UNVERIFIED=false`.
3. برنامهٔ اندروید: آزمایش روی دستگاه، آیکون واقعی، امضای release (keystore بیرون از مخزن)، تست‌های UI، اسکن کارت ملی (اختیاری)، آدرس سرور در build با `-PapiBaseUrl=https://shch.badr-group.ir/`.
4. پشتیبان‌گیری/بازیابی واقعی (`restore-drill.sh`)، مانیتورینگ، چرخش کلیدهای رمزنگاری (ابزارش هنوز نیست)، آزمون نفوذ.
5. PWA/وب (پوشهٔ `deploy/pwa` فعلاً خالی است) اگر لازم شد.

## قواعد کار
- قبل از هر تغییر `README.md`ها و `docs/` را بخوان. تغییرات کوچک و متمرکز؛ تست بنویس. بک‌اند: `go vet ./... && go test -race ./...` (نیاز به `TEST_DATABASE_URL`، `TEST_REDIS_URL`، `TEST_ALLOW_RESET=1`؛ پایگاه‌داده را پاک می‌کند، هرگز روی دادهٔ واقعی نزن). اندروید: `cd android && ./gradlew -c settings-core.gradle.kts :core:test`.
- هرگز secrets، کلیدها، رمز SSH یا دادهٔ زائران را در مخزن، لاگ یا چت نگذار. قبل از هر کار مخرب یا اثرگذار روی سرور تولید از من بپرس.
- صادق باش: آنچه اجرا و تأیید نکرده‌ای را «انجام‌شده» نگو.

اول مخزن را بخوان، وضعیت سرور را (فقط خواندنی) بررسی کن و بگو چه چیزهایی از «کارهای باز» واقعاً مانده؛ بعد از تأیید من شروع کن.
